# 2.19 — What it passes on, it also filters: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A port rule can name traffic this host forwards to a container, so easywall can be the only firewall on a container host.

**Architecture:** `PortRule` gains a `Scope` field (`host` / `forwarded` / `both`, default `host`). A new `docker.published_ports` key (`open` / `filtered`, default `open`) switches on a default-deny for inbound-to-container in easywall's existing `forward` chain. Nothing is written outside `table inet easywall`; the verdict is taken in easywall's own forward chain, where a drop already beats another table's accept.

**Tech Stack:** Go 1.25, `github.com/google/nftables`, Go templates + htmx, Tailwind 4, Jekyll for docs.

**Spec:** `docs-tech/specs/2026-09-12-2.19-what-it-passes-on-it-also-filters.md` — read it first; the ordering trap in §3a and §4 is the whole risk of this release.

## Global Constraints

- **easywall touches exactly one table: `table inet easywall`.** No task may write to `DOCKER-USER`, `ip filter`, or any other table. A change that needs that is a different release.
- **Default behaviour does not change.** A `rules.json` and an `easywall.toml` written before this release must produce a byte-identical ruleset after it. `Scope` defaults to `host`; `published_ports` defaults to `open`.
- **`[docker]` keys get no environment variable.** `docs/_docs/environment.md:91` states the rule — rule settings are written by the interface, because a variable would be silently undone on the next container restart. `published_ports` follows it.
- **Locale parity: `en` and `de` stay at exact key parity.** `fr` may lag. Every new UI string lands in both.
- **A test is verified by breaking the code, not by reading it.** Every task's test step includes mutating the implementation and confirming the test goes red.
- **A generated file is rebuilt and diffed, never assumed.** `web/static/style.css` and any changed screenshot are rebuilt in the task that changed their source.

	PublishedPortsFiltered = "filtered"

// FiltersPublishedPorts reports whether the forward chain takes verdicts on

func (d DockerConfig) FiltersPublishedPorts() bool {

```go
// buildForwardChain writes every rule in the forward chain, in the one order
// that makes them mean anything.
//
// It exists as a function rather than as a run of calls inside Apply because
// the order is the correctness of this release and Apply cannot be unit-tested
// — it needs a netlink connection. TestForwardChain_PortRulesComeBeforeTheExceptions
// drives this directly through the recording adder, and it is the only thing
// standing between this release and the defect it was written to fix.
func (m *NftablesManager) buildForwardChain(
	t *nftables.Table, c *nftables.Chain, rules shared.Rules,
	docker shared.DockerConfig, routing shared.RoutingConfig, dockerCIDRs []string,
) {
	if routing.Mode == shared.RoutingOpen {
		// The policy already accepts, so the exceptions would be dead weight —
		// but a forwarded deny is not. It is the only thing in this chain that
		// says no, and dropping it because another key is set is exactly the
		// silent no-op this release exists to end.
		m.addForwardPortRules(t, c, rules, docker, dockerCIDRs)
		return
	}

	forwardCIDRs := dockerCIDRs
	if routing.Mode == shared.RoutingNetworks {
		forwardCIDRs = append(append([]string(nil), dockerCIDRs...), routing.Networks...)
	}

	// Before the exceptions, never after. addForwardExceptions accepts any packet
	// with a bridge address at either end, and after Docker's DNAT an inbound
	// packet to a published port has one — so a forwarded rule placed after it
	// could never deny anything, and would report itself enforcing while
	// enforcing nothing.
	m.addForwardPortRules(t, c, rules, docker, dockerCIDRs)
	m.addForwardExceptions(t, c, forwardCIDRs)
}
```

// port, or fails. It fails rather than returning -1 so that a missing rule is
// reported where it is looked for, not as a baffling index comparison.
func indexOfDport(t *testing.T, rules []*nftables.Rule, port uint16) int {
	t.Helper()
	for i, r := range rules {
		if ruleMatchesDport(r, port) {
			return i
		}
	}
	t.Fatalf("no rule in the chain matches port %d", port)
	return -1
}

// indexOfVerdict returns the position of the first rule carrying the given
// verdict kind after the given index, or fails.
func indexOfVerdict(t *testing.T, rules []*nftables.Rule, kind expr.VerdictKind, from int) int {
	t.Helper()
	for i := from; i < len(rules); i++ {
		if ruleVerdict(rules[i]) == kind {
			return i
		}
	}
	t.Fatalf("no rule with verdict %v at or after %d", kind, from)

// THE test of this release. A forwarded rule rendered after the CIDR exception
// can never deny anything, because the exception has already accepted every
// packet with a bridge address at either end — and after Docker's DNAT, an
// inbound packet to a published port has one. A test that only asserted "the
// rule is present" would pass on a ruleset that enforces nothing, which is the
// exact shape of the defect 2.17 was built to convict.
func TestForwardChain_PortRulesComeBeforeTheExceptions(t *testing.T) {
	rules := buildForward(t, filteredDocker(), shared.RoutingConfig{Mode: shared.RoutingClosed},
		shared.Rules{TCP: []shared.PortRule{
			{Port: "25", Description: "SMTP", Scope: shared.ScopeForwarded},
		}},
		[]string{"172.17.0.0/16"})

	accept := indexOfDport(t, rules, 25)
	deny := indexOfVerdict(t, rules, expr.VerdictDrop, accept)
	exception := indexOfVerdict(t, rules, expr.VerdictAccept, deny)

	if !(accept < deny && deny < exception) {
		t.Fatalf("order is accept=%d deny=%d exception=%d; the port rule and the "+
			"deny must both precede the exception, or neither can refuse anything",
			accept, deny, exception)
	}

// matches a container's own outbound traffic, whose source is the bridge range,
// and every container on the host loses the network at the next apply — the
// failure the acceptance window cannot see, because SSH arrives on input.
func TestForwardChain_TheDenyTestsBothDirections(t *testing.T) {
	rules := buildForward(t, filteredDocker(), shared.RoutingConfig{Mode: shared.RoutingClosed},
		shared.Rules{}, []string{"172.17.0.0/16"})

```go
// addForwardPortRules renders the rules that let a named port reach a container,
// and the deny that gives them meaning.
//
// It does nothing at all unless docker.published_ports is "filtered". That is
// not a convenience: the deny below closes every published port that has no
// forwarded rule, and arriving switched on would take every container host's
// services off the network at its next apply — 2.5.0 with a different cause.
//
// ct state is deliberately not tested here. addEstablishedAccept runs at the top
// of this chain, so anything reaching these rules is new or invalid already, and
// a second state test would be a second place for the two to disagree.
func (m *NftablesManager) addForwardPortRules(
	t *nftables.Table, c *nftables.Chain, rules shared.Rules,
	docker shared.DockerConfig, cidrs []string,
) {
	if !docker.FiltersPublishedPorts() {
		return
	}

	for _, proto := range []struct {
		name  string
		rules []shared.PortRule
	}{{"tcp", rules.TCP}, {"udp", rules.UDP}} {
		for _, rule := range proto.rules {
			if !rule.FiltersForwarded() {
				continue
			}
			for _, r := range portAcceptRules(t, c, proto.name, rule) {
				m.adder.AddRule(r)
			}
		}
	}

	// The deny, once per bridge network, after the accepts and before the
	// exceptions. A container's outbound traffic has its *source* in the bridge
	// range and container-to-container has both ends inside, so neither matches;
	// only traffic arriving from outside for a container address does, which is
	// exactly a published port.
	for _, cidr := range cidrs {
		dst := cidrMatch(cidr, posDstAddr)
		src := cidrMatchNegated(cidr, posSrcAddr)
		if dst == nil || src == nil {
			continue
		}
		exprs := append(append([]expr.Any(nil), dst...), src...)
		m.adder.AddRule(&nftables.Rule{
			Table: t, Chain: c,
			Exprs: append(exprs, &expr.Counter{}, &expr.Verdict{Kind: expr.VerdictDrop}),
		})
	}
}
```

Add `cidrMatchNegated` beside `cidrMatch`, identical but emitting
`expr.CmpOpNeq` where `cidrMatch` emits `expr.CmpOpEq`.
