# 2.13 — "Behind a proxy, easywall knows who you are" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A list of trusted proxy addresses, set from the environment or the
file; when the TCP peer is on that list — and only then — `X-Forwarded-For` is
read and the resolved client becomes the address in the audit log, the address
the reachability verdict reasons about, and the key the login rate limiter
counts on. Demo mode records no login address at all.

**Architecture:** One resolution function, `resolveClient(r, trusted)`, in a new
`internal/web/clientaddr.go`, returning `(address, proxied)`. Every surface that
used to call `clientIP(r)` and `proxiedRequest(r)` separately now calls
`s.clientAddr(r)`, which is that function bound to the configured list. The
matcher is `shared.inAnyEntry` — the same "bare address or CIDR" walk the
whitelist and blacklist already use — exported rather than reimplemented,
because a second address matcher is the exact shape of the bug the three
advisories describe. `LoginRateLimit` gains a resolver parameter so the
middleware keys on the resolved client without learning about `Config`. The
proof is a veth test in `internal/web`: a real kernel-assigned peer address,
because a `httptest.Request` with a hand-set `RemoteAddr` proves nothing about
the path that matters.

**Tech Stack:** Go 1.x, `net/netip`, `github.com/BurntSushi/toml`,
`golang.org/x/time/rate`, chi router, `unshare`/`nsenter`/`ip` for the network
namespace, `bash`'s `/dev/tcp` for the raw HTTP client, Playwright via
`scripts/ui-check.mjs`.

**Spec:** `docs-tech/specs/2026-08-28-2.13-behind-a-proxy.md`

## Global Constraints

Every task's requirements implicitly include these.

- **A list, never a boolean.** `trusted_proxies` is `[]string`. A boolean that
  says "trust the header" is GHSA-3fxj-6jh8-hvhx, GHSA-rjr7-jggh-pgcp and
  GHSA-9g5q-2w5x-hmxf. No task may add one, not as a shortcut, not as a
  convenience wrapper.
- **The empty list is byte-identical to 2.12.** Default, and the only default.
  `resolveClient(r, nil)` must equal `(peerIP(r), proxiedRequest(r))` for every
  request shape. This is Task 2 Step 1, not an intention.
- **Being on the list is total trust in that peer.** Documented in those words
  in `docs-tech/threat-model.md` and in the operator page.
- **Only `X-Forwarded-For`'s value is ever read.** See Finding C.
- **Every assertion must fail when the feature is reverted.** Each task carries
  a mutation step: break the code, watch the test go red, restore. A test whose
  failure mode has not been observed does not count as written.
- **`docs-tech/` is never published.** Plans, specs and technical pages stay
  outside `docs/`. `TestTheTechnicalDocsAreNotPublished` enforces it.
- **No new visible strings.** This release adds no locale key. `en` and `de`
  stay at exact parity by adding nothing to either. If a task finds itself
  writing a `locales/*.json` entry, it has left the spec's scope.
- **Commit format** is the repository's — see `CONTRIBUTING.md`. Every task ends
  in one commit.

## Eight findings that shape the plan

Read these before Task 1. Each was verified against the tree on 2026-08-28.

**A · The roadmap amendment has already landed.** Spec §0 asks for
`docs/_docs/roadmap.md` to move the trusted-proxy list out of 3.0. Commit
`0fb5e74` already did it: line 21 and line 56 carry 2.13 as its own row, line 45
says in prose that "2.13 also takes the trusted-proxy list out of 3.0's row",
and the 3.0 row (line 65) names only the REST API and ACME. Task 7 **verifies**
this and does not redo it. Only the threat-model amendment is still owed.

**B · CI never runs a web-side integration test.**
`.github/workflows/test.yml:96` is
`sudo go test -tags integration … ./internal/core/...`. The spec's four proofs
live in `internal/web`. Without widening that path they would be green in CI
while never executing once — which is precisely the failure §4.4 names ("2.11
produced five tests that were green while proving nothing"). Task 6 widens the
path **and** adds a guard test so it cannot narrow again.

**C · Only `X-Forwarded-For` can carry the rightmost-untrusted rule.** §2's
algorithm is list-shaped: walk right to left past trusted hops.
`X-Real-IP` and `True-Client-IP` hold a single address with no hop semantics,
and `Forwarded` (RFC 7239) is a different grammar (`for=…;proto=…`) whose
parsing is a second attack surface for no gain. **Assumption, stated openly and
documented:** `X-Forwarded-For` is the only header whose *value* is read. All
four stay presence markers for the untrusted case, exactly as today. An operator
whose proxy sends only `X-Real-IP` gets the peer address and the `via-proxy`
marker — the 2.12 behaviour — not a wrong answer.

**D · The environment table has no list kind.** `shared.EnvKind` is
`EnvString | EnvBool` (`internal/shared/env.go:29-36`). Two guards break on a
third: `TestTheEnvironmentPageStatesTheRightTypes`
(`internal/shared/env_docs_test.go`) errors on a kind its `want` map has no
wording for, and `sampleValue` (`internal/shared/env_precedence_test.go:257`)
would hand `"/from-the-environment/rt-trusted_proxies"` to a validating `Set`.
Both are Task 1's problem, not a later surprise.

**E · The matcher already exists.** `shared.inAnyEntry`
(`internal/shared/reach.go`) is exactly "a bare address or a CIDR network, with
comments and blanks skipped", already used by the whitelist, the blacklist and
the port source lists. Task 1 exports it. Writing a second one is how the list
check and the rule check come to disagree, and a mistake in the list check is
the rate-limiter bypass this whole release is a proof about.

**F · Demo suppression has exactly one funnel.** Both `Server.recordLoginEvent`
(`server.go:451`) and `Server.onLoginBlocked` (`server.go:459`) go through
`auditEvents.Record` (`auditevents.go:38`). Blanking the address there is the
whole change: the core's `addrDetail("")` (`internal/core/loginevents.go:208`)
already returns `""`, and the demo's `handleLogEvent` already guards on
`if p.Addr != ""` (`democlient.go:675`). No third place needs touching.

**G · The `/log` screenshots are taken against demo mode.**
`scripts/ui-check.mjs` signs in and shoots `/log` (its page list, line 59), so
`docs/assets/img/screens/log-dark.png` and `log-light.png` show a login line
whose detail reads `from 127.0.0.1`. Task 5 removes that detail; Task 8 re-takes
both images in the same change.

**H · The integration namespace needs `lo` brought up.** `internal/core`'s
`TestMain` re-execs into `CLONE_NEWNET` (`integration_test.go:19-41`) and never
raises loopback — harmless there. `internal/web` has four test files that
`net.Listen` or use `httptest` (`client_test.go`, `client_timeout_test.go`,
`tlscert_test.go`, `testhelpers_test.go`), and a `TestMain` in that package
applies to **all** of them under `-tags integration`. Without
`ip link set lo up` the whole web suite fails inside the namespace with
"connect: network is unreachable". Task 6's `TestMain` raises it.

func TestTrustedProxiesComesFromTheEnvironmentAsAList(t *testing.T) {
	v, ok := WebEnvVar("trusted_proxies")

// ValidateProxyList checks a trusted-proxy list: bare addresses and CIDR
// networks, the two shapes every other address list in the product accepts,
// with comments and blanks skipped the same way.
//
// A malformed entry stops startup. Dropping it instead would leave a list one
// entry short, which stops trusting a proxy that is really there — and the
// operator meets that as a login limiter that suddenly counts everyone
// together, six weeks later, with nothing anywhere naming the typo.
func ValidateProxyList(entries []string) error {
	for _, entry := range entries {
		if IsListComment(entry) {
			continue
		}
		if err := ValidateIPOrCIDR(strings.TrimSpace(entry)); err != nil {
			return fmt.Errorf("trusted_proxies %q: %w", entry, err)
		}
	}
	return nil
}

// splitList parses the comma-separated form a list variable carries. Empty
// fields are dropped, so a trailing comma is a trailing comma and not an entry
// nobody can parse.
func splitList(v string) []string {
	var out []string
	for _, part := range strings.Split(v, ",") {
		if p := strings.TrimSpace(part); p != "" {
			out = append(out, p)
		}
	}
	return out
}
```

import (
	"net/http"
	"net/http/httptest"
	"testing"
)

// request builds a request with a peer address and any number of headers,
// given as name/value pairs.
func request(t *testing.T, peer string, headers ...string) *http.Request {
	t.Helper()
	if len(headers)%2 != 0 {
		t.Fatalf("headers come in pairs, got %d values", len(headers))
	}
	r := httptest.NewRequest("POST", "/login", nil)
	r.RemoteAddr = peer
	for i := 0; i < len(headers); i += 2 {
		r.Header.Add(headers[i], headers[i+1])
	}
	return r
}

// The empty list is 2.12, byte for byte. Every other guarantee in this release
// rests on an installation that configures nothing behaving as it always did,
// so this is a test and not an intention.
func TestTheEmptyListIsTwoPointTwelve(t *testing.T) {
	for _, tc := range []struct {
		name string
		r    *http.Request
	}{
		{"no header", request(t, "203.0.113.7:5555")},
		{"a forwarded-for header", request(t, "203.0.113.7:5555",
			"X-Forwarded-For", "10.9.9.9")},
		{"a real-ip header", request(t, "203.0.113.7:5555",
			"X-Real-IP", "10.9.9.9")},
		{"several hops", request(t, "203.0.113.7:5555",
			"X-Forwarded-For", "10.9.9.9, 10.8.8.8")},
		{"a peer with no port", request(t, "203.0.113.7")},

package web

import (
	"net"
	"net/http"
	"net/netip"
	"strings"

	"github.com/jp1337/easywall/internal/shared"
)

// Who a request is from.
//
// Until 2.13 the answer was one line: the TCP peer, always, because a
// forwarding header is written by whoever is on the other end of the socket and
// easywall-web is not assumed to sit behind anything. That is still the answer
// when nothing is configured, and the empty list is the default —
// TestTheEmptyListIsTwoPointTwelve holds the two paths byte-identical.
//
// What 2.13 adds is a *list* of peers whose header is believed. Never a
// boolean: "trust the header" with no way to say whose is exactly
// GHSA-3fxj-6jh8-hvhx, GHSA-rjr7-jggh-pgcp and GHSA-9g5q-2w5x-hmxf, and
// docs-tech/threat-model.md carries the argument in full.

// proxyHeaders are the headers whose *presence* means the peer is not the
// client. Only X-Forwarded-For's value is ever read — see resolveClient.
var proxyHeaders = []string{"X-Forwarded-For", "X-Real-IP", "True-Client-IP", "Forwarded"}

// peerIP is the TCP peer address, and only the peer address.
func peerIP(r *http.Request) string {
	ip, _, err := net.SplitHostPort(r.RemoteAddr)
	if err != nil {
		return r.RemoteAddr
	}
	return ip
}

// proxiedRequest reports whether this request arrived through something that
// forwards, so the interface can say that the address it recorded is not the
// caller's.
//
// Presence only, and it is consulted only when the peer is *not* trusted. A
// client that forges a header from an untrusted peer can move its own verdict
// to "cannot tell" and its own login line to via-proxy, and achieve nothing
// else: the recorded address is still the peer's. That asymmetry is the whole
// argument for reading an untrusted header at all.
func proxiedRequest(r *http.Request) bool {
	for _, h := range proxyHeaders {
		if _, ok := r.Header[http.CanonicalHeaderKey(h)]; ok {
			return true
		}
	}
	return false
}

// resolveClient answers who this request is from, and whether that address is a
// stand-in for somebody it cannot name.
//
// The peer decides which of the two branches runs, and the peer is the one
// thing on a request nobody can write: it comes from the kernel's copy of the
// socket. If it is on the list, X-Forwarded-For is read; if it is not, the
// header's value is never looked at, exactly as before 2.13.
//
// proxied is false whenever the peer is trusted — the address returned is then
// the client's own, and marking it via-proxy would say the opposite of what is
// true. It stays true for an untrusted peer sending any of the four headers,
// which is 2.10's behaviour unchanged.
func resolveClient(r *http.Request, trusted []string) (string, bool) {
	peer := peerIP(r)
	addr, err := netip.ParseAddr(peer)
	if err != nil || !shared.InAnyEntry(addr.Unmap(), trusted) {
		return peer, proxiedRequest(r)
	}
	return rightmostUntrusted(r, trusted, peer), false
}

// rightmostUntrusted walks X-Forwarded-For from the right and returns the first
// hop that is not itself a trusted proxy.
//
// From the right, because the chain is appended to: everything to the left of a
// hop was written by whoever was talking to that hop, and the caller controls
// the left-hand end completely. Walking past trusted entries is what stops a
// caller writing "X-Forwarded-For: 10.1.0.5" — a proxy's own address — and
// being handed that identity; the veth test's third case is exactly that.
//
// X-Forwarded-For alone. X-Real-IP and True-Client-IP carry one address with no
// hop semantics, and Forwarded (RFC 7239) is a different grammar whose parser
// would be a second surface for no gain. All four still mark an untrusted
// request through proxiedRequest.
//
// An entry that is not an address ends the walk at the peer rather than being
// skipped: everything left of it was written by whatever put it there, and a
// hop that is not an address is not one this can reason past.
func rightmostUntrusted(r *http.Request, trusted []string, peer string) string {
	var hops []string
	for _, v := range r.Header.Values("X-Forwarded-For") {
		for _, part := range strings.Split(v, ",") {
			hops = append(hops, strings.TrimSpace(part))
		}
	}
	for i := len(hops) - 1; i >= 0; i-- {
		addr, err := netip.ParseAddr(hops[i])
		if err != nil {
			return peer
		}
		if a := addr.Unmap(); !shared.InAnyEntry(a, trusted) {
			return a.String()
		}
	}
	return peer
}
```

func (h *peerHarness) run(args ...string) {
	h.t.Helper()
	if out, err := exec.Command(args[0], args[1:]...).CombinedOutput(); err != nil {
		h.t.Skipf("skipping: %s: %v: %s", strings.Join(args, " "), err, out)
	}
}

func (h *peerHarness) inNS(args ...string) {
	h.t.Helper()
	h.run(append([]string{"nsenter", "-t", h.pid, "-n"}, args...)...)
}

// get issues one HTTP request from inside the namespace and returns the whole
// response. bash's /dev/tcp rather than curl, which is not installed on every
// runner; plain HTTP rather than TLS for the same reason — this test is about
// the peer address, and TLS would add a dependency without adding a claim.
//
// The request goes in as printf's *format string*, which is what turns the
// literal \r\n sequences below into a real CRLF. Nothing here may contain a
// percent sign for the same reason.
func (h *peerHarness) get(path string, headers ...string) string {
	h.t.Helper()
	req := "GET " + path + " HTTP/1.0\\r\\nHost: " + harnessServer + "\\r\\n"
	for _, hdr := range headers {
		req += hdr + "\\r\\n"
	}
	req += "\\r\\n"

	script := fmt.Sprintf(
		"exec 3<>/dev/tcp/%s/%s; printf '%s' >&3; cat <&3",
		harnessServer, h.port, req)
	out, err := exec.Command("nsenter", "-t", h.pid, "-n",
		"timeout", "5", "bash", "-c", script).CombinedOutput()
	if err != nil {
		h.t.Fatalf("request from the namespace failed: %v: %s", err, out)
	}
	return string(out)
}

// serve starts an HTTP server on the near side of the veth and records the port
// the harness's client should reach it on.
//
// httptest builds the server and then has its listener swapped, because
// httptest binds 127.0.0.1 and the whole point here is an address the client
// reaches over a wire.
func (h *peerHarness) serve(handler http.Handler) {
	h.t.Helper()
	ln, err := net.Listen("tcp", harnessServer+":0")
	if err != nil {
		h.t.Skipf("skipping: cannot listen on %s: %v", harnessServer, err)
	}
	srv := httptest.NewUnstartedServer(handler)
	_ = srv.Listener.Close()
	srv.Listener = ln
	srv.Start()
	h.t.Cleanup(srv.Close)
	_, h.port, _ = net.SplitHostPort(ln.Addr().String())
}

// about a value computed from a real socket rather than about a page.
func resolveHandler(trusted []string) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		addr, proxied := resolveClient(r, trusted)
		fmt.Fprintf(w, "client=%s proxied=%v", addr, proxied)
	})
}

// executing once. That is the failure spec §4.4 names — 2.11 produced five

func TestTheIntegrationJobCoversEveryTaggedPackage(t *testing.T) {
	block := jobBlock(t, repoFile(t, ".github", "workflows", "test.yml"), "test-integration")

	for _, line := range strings.Split(block, "\n") {
		if trimmed := strings.TrimSpace(line); strings.HasPrefix(trimmed, "run: sudo go test") {
			cmd = trimmed
			break
		}
	}

		t.Fatal("the integration job does not run go test")
	}

	// Derived from the tree, not restated: any package that grows a file behind
	// the integration tag has to appear in the command.
	root := repoRootDir(t)

		dir := filepath.Join(root, "internal", pkg)
		entries, err := os.ReadDir(dir)
		if err != nil {
			t.Fatalf("read %s: %v", dir, err)
		}
		tagged := false
		for _, e := range entries {
			if e.IsDir() || !strings.HasSuffix(e.Name(), "_test.go") {
				continue
			}
			data, err := os.ReadFile(filepath.Join(dir, e.Name()))
			if err != nil {

				break
			}

		}

### What the list defends, and what being on it costs

| | |
|---|---|
| Decided by | the TCP peer — the one field on a request nobody can write |
| Read when the peer is on the list | `X-Forwarded-For`, and nothing else |
| The client | the rightmost hop that is not itself on the list; the peer when there is none |

```

or `EASYWALL_WEB_TRUSTED_PROXIES=127.0.0.1,10.1.0.5`.

**What it buys.** Behind a proxy every request otherwise appears to come from the
proxy: the audit log records the proxy's address, the apply screen cannot tell
you whether you are about to lock yourself out, and the login limiter's five
attempts per ten minutes are shared by everyone — one attacker exhausts them for
you. With the proxy listed, all three see the real client.

**What it costs.** Being on this list is total trust in that peer. Two mistakes
hand address spoofing to anyone who can reach the port:

- listing an address that is **not** actually a proxy in front of easywall;
- listing a **network** rather than the proxies themselves — every host in
  `10.0.0.0/8` can then choose the address easywall records, verdicts on, and
  rate limits.

List the proxies. Not the subnet they live in, not `0.0.0.0/0`, and never an
address you do not control.

Only `X-Forwarded-For` is read. `X-Real-IP`, `True-Client-IP` and `Forwarded`
still mark a request as arriving through something that forwards, but their
values are never used — configure your proxy to send `X-Forwarded-For`.
```
