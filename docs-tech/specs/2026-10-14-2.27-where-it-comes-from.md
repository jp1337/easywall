# 2.27 — Where it comes from

/blocked shows the country each refused source address is delegated to, and a
row can stage that country for blocking. The lookup table is ipverse's whole
dataset, loaded by the web process once a day; the core learns nothing new.

**Why now.** 2.26 lets an operator block a country, but /blocked names a country
only for packets a country rule refused. Which countries the other drops come from —
the question that leads to switching one on — is not answered anywhere.

## 0 · Decisions, and what decided them

| # | Decision | Evidence |
|---|---|---|
| D1 | **Source: ipverse's release archive** `https://github.com/ipverse/country-ip-blocks/releases/latest/download/country-ip-blocks.tar.gz`, once a day, conditional (ETag / Last-Modified). Only `country/*/aggregated.json` is read. | Measured 2026-10-14: 1 747 173 bytes; 238 countries, **178 893 IPv4 + 69 614 IPv6** prefixes; `ETag` and `Last-Modified` present; CC0 like 2.26's per-country files. 238 single files would be 238 requests a day. |
| D2 | **The download follows redirects to exactly two hosts**: `github.com` and `release-assets.githubusercontent.com`, HTTPS only, at most 3 hops. Every other redirect is refused. | Measured: `github.com/…/latest/download/…` → 302 `github.com/…/download/latest/…` → 302 `release-assets.githubusercontent.com/…`. The feed fetcher refuses every redirect (2.23), so this is a separate, narrower client — not a loosening of the feeds'. |
| D3 | **On by default.** The `web.toml` key `country_lookup = true`, with the documented `EASYWALL_WEB_COUNTRY_LOOKUP`; `false` makes no request and renders no column. A host whose `web.toml` predates the key reads `true` (an explicit `meta.IsDefined` fallback — `LoadConfig` decodes into a zero `Config`, the 2.25 trap). *(Amended 2026-10-14 by the maintainer: the first version had it off by default. The upgrade therefore starts one new outbound request a day to github.com; the changelog, privacy and security pages say so.)* | The maintainer's decision. |
| D4 | **The table lives in the web process, in memory**, as sorted, merged ranges per family; a lookup is a binary search. Persisted to `data_dir/web/countries.tar.gz` so a restart does not refetch. | ≈ 250 000 ranges — the plan measures RSS and lookup time and states both. The core never sees it: a lookup is a label, not a rule. |
| D5 | **/blocked gains a column *Country*** — the code (`RU`), the localised name as the cell's title (x/text `display`, 2.26's `countryName`). Unknown, private or not yet loaded: `—`. On the 390 card layout it is one more labelled line. | The delta tail (2.25.2) renders rows with the same template, so new rows carry the column. |
| D6 | **A row action *Block country*** stages `country-<cc>` exactly as the 2.26 card's Add does — same cap, same refusal, same flash — and only when the country is not already staged. It never applies. | Every /blocked action stages and returns to the view (2.21 rule). |
| D7 | **No country filter** in this release. | The filter goes to the core, which has no table (D4). Filtering the web side of a 200-row answer would silently filter a sample. Roadmap note instead. |
| D8 | **The words say delegation, not location.** The column header's title and the docs: "the country the address block is registered to; VPNs, clouds and Tor exits do not follow it". | Same caveat as 2.26's countries.md. |

## 1 · Web

- A `countryTable` built from the archive: parse every `aggregated.json`, reuse 2.26's prefix validation, merge, sort; swap atomically when a new copy loads. A failed fetch keeps the last table.
- A daily refresh beside the feed runner, at the install's offset, conditional.
- Status (loaded, entries, last checked, last error) shown on /blocked when the lookup is on, one line.
- `blockedRows` gains the country per entry; the template renders the column and the action.

## 2 · Documentation

- `blocked-traffic.md`: the column, the action, the switch, the delegation caveat.
- `configuration.md`: the key.
- `privacy.md` / `security.md`: the new outbound request, when it is on, and to which hosts.
- `countries.md`: a link from the "which countries?" question to the column.
- Screenshots of /blocked with the lookup on (demo: a small built-in table).

## 3 · Proof

| Test | Proves |
|---|---|
| unit | a v4 and a v6 address resolve to the right country; a private address, an address between ranges and an empty table give none |
| unit | the archive parser reads only `aggregated.json`, refuses a truncated archive and keeps the old table |
| unit | redirects: the two hosts pass, a third host, plain HTTP and a fourth hop are refused |
| unit | off: no request is made and no column is rendered |
| unit | the action stages `country-<cc>`, respects the cap, is absent when the country is already staged |
| benchmark | the full table: build time, memory, lookup time — numbers in the plan and the docs |
| `check:ui` + Chrome | the column and the action in both themes at 1600 / 900 / 390, de and en |

## 4 · Out of scope

- A country filter on /blocked (D7).
- City or ASN data; any provider that needs an account or a licence key.
- A world map.

## 5 · Release

2.27.0, after 2.26. The roadmap rows from *What it counts can be asked for*
onward move one place. Field check: switch the lookup on in the demo; on prod
only if the operator does, then count drops per country (counts only).
