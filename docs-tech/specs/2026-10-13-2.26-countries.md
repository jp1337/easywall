# 2.26 — Countries

An operator can block the address space of individual countries. Each country
is switched on by itself, all are off by default, and the rules sit after the
allowlist like every feed. Under the hood a country *is* a feed with its own id
range, so fetching, storing, counting, the shrink guard, the lockout check and
the packet log are the 2.23 machinery, unchanged.

**Why now.** Roadmap 2.29, pulled forward on the maintainer's request. The
roadmap planned to build this from the RIRs' delegation files. That would mean
≈46 MB a day across five files, written as start address plus count rather
than as prefixes, which we would have to split and aggregate ourselves.
ipverse publishes that same aggregation per country instead.

## 0 · Decisions, and what decided them

| # | Decision | Evidence |
|---|---|---|
| D1 | **Block only, on every port.** No "allow only these countries", and no per-port scope. | Maintainer's choice. Allow-mode is a lockout risk of its own and overlaps roadmap 2.38 (per-feed ports). |
| D2 | **Source: [ipverse/country-ip-blocks](https://github.com/ipverse/country-ip-blocks)**, `country/<cc>/ipv4-aggregated.txt` and `ipv6-aggregated.txt` from `raw.githubusercontent.com`. | CC0 1.0. Built daily from all five RIRs' delegations: the last 5 commits were 01:23–01:25 UTC each day, and 238 country directories exist. Plain text, one prefix a line, five `#` header lines, which `FeedFormatPlain` already reads. Every file answers with an `ETag`, so the existing If-None-Match makes a daily refresh cost nothing when nothing changed. Sizes on 2026-10-13: CN 5 514 + 2 035, RU 8 660 + 2 169, DE 8 746 + 3 091, US 29 690 + 10 685 prefixes (v4 + v6). The largest file is 464 KB. One maintainer: if the source goes away, every country keeps its last copy, like any feed. |
| D3 | **A country is a feed with id `country-<cc>`** (ISO 3166-1 alpha-2, lower case) and two URLs, v4 and v6, merged into one update. | `CatalogueFeed.URLs` already merges several URLs (Spamhaus has two). Sets `feed-country-de-v4/-v6` and log prefix `easywall feed: country-de ` fit the kernel's limits (`TestFeedLogPrefixesFitTheKernel` is extended). |
| D4 | **The switches live in `Rules.Feeds`**, beside the catalogue ids. | Staging, the diff on /apply, the acceptance window, rollback, export/import and the refresh loop (Staged ∪ Current) all walk `Rules.Feeds` already. A second list would duplicate every one of them. |
| D5 | **At most 30 countries.** `ValidateRules` refuses a 31st. | Every refresh reads GET_FEEDS for all ids and rewrites the whole of `feeds.json`, which is O(N²) in feeds. Every country adds 2 sets and 2–4 rules. A wish for "everything but DE" is the allow-mode of D1, which is out of scope. The integration test in §4 runs the 30 largest countries at their real sizes. If it fails, the cap goes down; it is not raised past what the test passes. |
| D6 | **The known codes are a list in `shared`**, the 238 directories ipverse has today. Each one must parse as a region in `golang.org/x/text/language`. | The core validates ids (`KnownFeedID`) without the network. A code ipverse later drops fails its fetch with a 404 and keeps its last copy (`failed_copy`). |
| D7 | **Names come from `golang.org/x/text/language/display`** in the page's language. No locale key per country. | Already in the module graph (indirect, v0.43.0), so this adds no new module. Measured: en *Germany / North Korea*, de *Deutschland / Nordkorea*, fr *Allemagne / Corée du Nord*. Adding 238 × 3 strings would be translation work that CLDR already did. |
| D8 | **A country is checked after the catalogue feeds and own feeds.** An address on both is attributed to the feed. | The order only decides which rule logs a packet; every set drops. The catalogue feeds say more about why an address is refused. |
| D9 | **Refresh every 24 h**, at the existing per-install offset. | The source changes once a day. |
| D10 | **The interface gets its own card, *Countries*, on /blocklist** under *Feeds*. Its table shows only the switched-on countries, with a select of all 238 (sorted by localised name, code shown) to add one. | The feed table stays at 8 + 3 rows. A table of 238 rows nobody switches on is a scroll bar, not information. |

## 1 · Core

- `KnownFeedID` accepts `country-<cc>` for a code in D6's list.
- `ValidateRules` counts the `country-` ids against D5.
- The rest is unchanged: `UpdateFeed`, `ReplaceFeedSet`, `feeds.json`, the shrink guard, the panic check and the apply slot.
- `addFeeds` renders the country feeds after the others (D8).

## 2 · Web

- **Catalogue lookup:** `CountryFeed(cc)` builds the `CatalogueFeed` with the two URLs, `plain`, 24 h and no verdict. `CatalogueFeedByID` and `FeedDisplayName` resolve `country-` ids. The name comes from D7 in the request's language, falling back to the upper-case code.
- **Form:** `POST /blocklist/countries` stages the country subset of `Rules.Feeds` and keeps every other id. Adding a country triggers `refreshFeedNow`, as switching on a feed does.
- **/blocked:** the chip reads *Country: Germany* (`blocked_rule_country_named`) and links to `/blocklist#country-de`. Filtering by rule `feed` still matches.
- **/apply:** the diff names the country. The lockout check needs nothing new, because GET_FEEDS with the operator's address already names any feed (country) holding it.
- **Demo:** the mock answers country ids as it answers feeds.
- **New locale keys** in en and de (fr may have gaps): the card's title and lead, the select, *Add*, *Remove*, the column heads it does not share with the feed table, `blocked_rule_country_named`, `feeds_error_too_many_countries`, and the crawler note (§3).

## 3 · Documentation

New page `docs/_docs/features/countries.md`, as a how-to plus a reference table.

**How-to:** add a country, apply, confirm.

**What it cannot do:**
- A delegation is where a block was *registered*, not where a packet comes from. VPNs, clouds and Tor exits do not follow it.
- Blocking only blocks. "Only these countries" is not this feature.
- Blocking US blocks Googlebot and Bingbot. The [feeds](/docs/features/feeds/) crawler note links here, and so does the card.

**Reference:** source, licence, update time, and the cap with its reason.

**Also:** `roadmap.md` loses row 2.29, and 2.26–2.28 move one place (§6). `feeds.md` links the new page. CHANGELOG 2.26.

## 5 · Out of scope

- Allow-mode and per-port scope (D1; roadmap 2.38).
- [ipverse/geo-ip-blocks](https://github.com/ipverse/geo-ip-blocks) (registration records, larger lists). Revisit if delegations prove too coarse.
- Continents or groups such as EU. One country is one switch.

## 6 · Release

2.26.0. The roadmap's rows 2.26 (metrics), 2.27 and 2.28 become 2.27–2.29, and
row 2.29 goes. After merge and tag: wdk-ansible rolls out. The field check
confirms nothing changed on prod: no `country-` id staged or current, the same
kernel rule count as before. The demo fetches no lists, so it proves only the
card. A country switched on in prod is the operator's decision, and its first
field check reads its GET_FEEDS row and the drops attributed to it. Counts only.
