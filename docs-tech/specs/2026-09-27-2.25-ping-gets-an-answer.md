# 2.25 — Ping gets an answer, if you want one

One switch, on by default, answers ping in both families. Every other ICMP
accept that conntrack already makes goes, so the input chain accepts exactly two
kinds of ICMP on its own: echo requests, when the switch says so, and IPv6
neighbour discovery.

**Why now.** The roadmap's 2.37, pulled forward. IPv4 echo requests met the
policy drop on every host while IPv6 ones were answered, with no switch for
either. RFC 1122 §3.2.2.6 says a host MUST answer an echo request; monitoring
expects it. The maintainer's rule, which this keeps: ICMP limited to what is
needed, and the operator decides about ping (FortiGate's model — ping is
explicitly allowed, never implied).

## 0 · Decisions, and what decided them

| # | Decision | Evidence |
|---|---|---|
| D1 | **One key, both families:** `[firewall] icmp_allow_echo_request = true` accepts ICMPv4 type 8 and ICMPv6 type 128. | Maintainer's choice (approach A). RFC 1122's reasoning is not per family; two keys is a knob nobody needs. Named like `icmp_allow_router_advertisement`. |
| D2 | **On by default**, including for a host whose `easywall.toml` predates the key. | RFC 1122. A missing key takes the embedded default (`env.go`, `coreDefault`), so an upgrade reads `true`; a test proves it. IPv4 ping is answered after the upgrade — a change toward open, named in the changelog. IPv6 is unchanged. |
| D3 | **The stateless accepts of ICMPv4 0, 3, 11, 12 and ICMPv6 1, 2, 3, 4, 129 go.** | `ct state established,related accept` runs before them (`nftables.go`, Apply). Linux 6.12: an echo reply to this host's own echo is `established` (`invmap`, `nf_conntrack_proto_icmp.c`); an ICMP error about a tracked flow is `related` (`nf_conntrack_inet_error`: `ctinfo = IP_CT_RELATED`); one about no flow gets no conntrack entry (`return -NF_ACCEPT`), which nft reads as `invalid`. So these rules admitted only unsolicited echo replies (an ICMP tunnel's carrier) and errors about connections that do not exist. Path-MTU discovery (v4 3/4, v6 2) and traceroute replies (11) stay accepted, as `related`. |
| D4 | **NDP stays stateless, behind its existing switches** (133/134, 135/136). | `nf_conntrack_icmpv6_error` sets them `IP_CT_UNTRACKED` (`noct_valid_new`); no `ct state` accept admits them. |
| D5 | **Behind the ICMP flood limiter, unchanged.** | It already precedes the established accept and matches type 8 and 128 (`addICMPFloodProtection`). Over the rate, dropped; under it, falls through to D1. |
| D6 | **No source list.** Monitoring-only ping: switch off, monitoring address on the allowlist. | Maintainer's choice. The allowlist rule matches the source and no protocol (`addAllowlistRule`), so it admits ping — and every port; the documentation says both. |
| D7 | **One source for the accepted types.** `shared` owns the lists, taking the switch; `addICMPRules` renders from them. | Today they are written twice (`packetlog.go` and `nftables.go`), held together by `TestICMPAcceptsAreTheListsDropReasonReads`, which stays. |
| D8 | Timestamp (13/14), address mask (17/18), redirect (5) and the rest stay dropped. | Not accepted today; nothing here adds them. Linux answers a timestamp request that reaches it, so the drop is what hides the clock. |

## 1 · The input chain

Order unchanged; the ICMP block shrinks:

```
loopback accept
ipv6 mode (passthrough accept / block drop)
icmp flood limiter                      over the rate: drop
ct state established,related accept     replies, and every genuine ICMP error
icmp   type 8   accept                  ┐ icmp_allow_echo_request = true
icmpv6 type 128 accept                  ┘ (icmpv6 only under ipv6.mode = "filter")
icmpv6 type 133,134 accept              icmp_allow_router_advertisement
icmpv6 type 135,136 accept              icmp_allow_neighbor_advertisement
… modules, docker, blocklist, allowlist, feeds, ports, custom
                                        policy drop
```

## 2 · Interface

| Place | Change |
|---|---|
| `/options`, *Attack protection* | New module **Answer pings** directly above *ICMP flood*, same shape (switch, protects/breaks, help). Breaks, when off: monitoring and `ping`-based checks. Help names the allowlist recipe and its cost (every port). |
| *ICMP flood* copy | "over IPv6, where pings are answered" goes |
| Blocked page | `DropIPv4Ping` (`ipv4_ping`) becomes **`DropPingOff`** (`ping_off`), both families: *Pings are switched off under Options.* with a link. A row whose type the rules now accept reads `icmp_accepted_now`; an unsolicited type 0 reads `icmp_type`. |
| Locales | `en`, `de` at parity; `fr` where its catalogue has the surrounding keys |

## 4 · Proof

Every test is seen red by breaking the code it covers.

| Test | Proves |
|---|---|
| unit, recording adder | switch on: type 8 and 128 accepts present; off: absent; no accept for 0, 3, 11, 12, 1–4, 129 in any case |
| unit | the rendered types equal the `shared` lists for every switch combination (the existing guard, extended) |
| unit | an `easywall.toml` without the key loads `true` |
| unit | drop reasons: type 8/128 with the switch off → `ping_off`; on → `icmp_accepted_now`; type 0 → `icmp_type` |
| integration, real kernel (podman) | ping answered with the switch on and dropped with it off, both families; this host's own ping gets its reply with the switch off; a traceroute time-exceeded (11) and a fragmentation-needed / packet-too-big error for a tracked flow arrive; a timestamp request (13) is dropped |
| `check:ui` + Chrome | the new module and the blocked reason in both themes at three widths |

## 5 · Out of scope

- A source list for ping (D6).
- Per-interface ping (roadmap *Every rule knows its interface*).
- MLD (130–132, 143): not accepted today, unchanged.
- `reject` for closed ports (roadmap *Whoever knocks gets locked out*).
