# 2.12 — The configuration comes from outside, and the page says so

Environment variables become the documented way to configure easywall, the
interface stops lying about where a value came from, and the doubled save button
goes.

Agreed with the maintainer on 2026-08-27. Every decision below was made
deliberately; where one went against a first instinct, the reasoning is kept.

## 0 · Roadmap position

This release and 2.13 are inserted after 2.11. Everything from the old 2.12
onward moves back two places. **3.0 and 3.1 keep their numbers** — those are
statements, not positions: 3.0 is a major because an API is a second public
interface and a compatibility promise, and 3.1 follows 3.0 because WebAuthn
needs a registrable hostname. Both stay true however many 2.x releases precede
them. `docs/_docs/roadmap.md` is renumbered as part of this release.

## 1 · Precedence inverts — and this is the decision everything hangs on

Today `applyEnv` (`internal/shared/env.go:93-96`) overlays the environment
**on top of** the parsed TOML, so the environment wins. The interface offers
controls for some of those keys and marks none of them, so an operator can
change the language in the interface, see it apply, and find it reverted after a
restart. That is the same dishonesty as a save button for a value already saved.

The new order, modelled on Vaultwarden at the maintainer's request:

```
stored value   (web.toml — hand-written or written by the interface)
     ^ beats
environment variable
     ^ beats
built-in default
```

**"Stored" must mean *the operator set this key*, never *the key is present in
the file*.** `easywall-web -write-config` emits a complete TOML with every
default, and that is exactly how Docker images are built — under the naive
reading such a file would silently disable every environment variable in the
product. This is the single most important requirement in this document.

Implementation: per-key presence detection. The pattern already exists —
`Config.Telemetry` is a `*bool` with three states (never asked, yes, no), read
through `TelemetryEnabled()` (`internal/web/config.go:230-236`). Either widen
that pattern to every overlaid key, or take presence from the TOML decoder's
metadata. Whichever is chosen, the guard test is not optional:

> Write a config with `-write-config`, set an environment variable whose key
> that file also contains at its default, start the process, and assert the
> environment value is in effect. This test fails on the naive implementation.

## 2 · The interface says where a value came from

Every setting with a control shows its provenance, and the control stays usable:

| Environment | Stored | In effect | The control shows |
|---|---|---|---|
| — | — | built-in default | nothing |
| set | — | the environment | *set by the environment* |
| set | differs | the stored value | *the environment says X — overridden here*, plus **reset to the environment value** |
| set | identical | the stored value | *set by the environment* — there is no conflict to display |
| removed | present | the stored value | nothing; the override is now the only value |
| set | reset | the environment | the marker returns |

Built generically, not for telemetry alone: the same template helper serves
every key, and the trap it removes exists today for all twelve variables, not
one. The scriptless page must render the marker too — these pages genuinely work
without JavaScript (see §4).

## 3 · The twelve variables

```
EASYWALL_CORE_SOCKET_PATH  socket_path     EASYWALL_WEB_DATA_DIR      data_dir
EASYWALL_CORE_DATA_DIR     data_dir        EASYWALL_WEB_TLS_CERT      tls.cert
EASYWALL_CORE_LOG_DIR      log_dir         EASYWALL_WEB_TLS_KEY       tls.key
EASYWALL_WEB_BIND_ADDR     bind_addr       EASYWALL_WEB_LANGUAGE      language
EASYWALL_WEB_SOCKET_PATH   socket_path     EASYWALL_WEB_UPDATE_CHECK  update_check
EASYWALL_WEB_SSL_DIR       ssl_dir         EASYWALL_WEB_DEMO_MODE     demo_mode
```

Plus one new: **`EASYWALL_WEB_TELEMETRY`** → `telemetry`, `EnvBool`.

The new precedence applies to **all thirteen uniformly**. The alternative — one
rule for keys with a control, another for paths and sockets — was rejected: two
rules in one system means "which rule applies to this key?" becomes a question
somebody has to look up.

**This is a behaviour change for existing Docker installations** and belongs in
the CHANGELOG under *Changed*: a value that was once set in the interface, or
written by hand into `web.toml`, now beats the environment variable. The reset
control is the way back.

## 4 · The doubled save button

`/options`, `/system` and `/settings` each post over HTMX on `change` **and**
carry a Save button. Four forms in three templates carry
`hx-trigger="change delay:200ms"`: `options.html:28`, `settings.html:27`,
`system.html:33` and `system.html:74`.

The button is **not** redundant. All three forms have `method="POST"` and a real
`action`, and their inputs carry names — so without JavaScript the button is the
only way to save, and these pages genuinely work scriptless. (This is the
opposite of the ports and forwarding editors, whose row inputs carry no `name`
at all; that was established during 2.11 and is documented there.)

**Decision: manual save only.** Remove `hx-trigger` from all four forms. htmx
falls back to a form's `submit` trigger, so the toast and the reload-free save
survive; only the automatic write on every change goes. The maintainer chose
this over hiding the button when JavaScript is present.

## 5 · Telemetry, switched on and proven

The endpoint at `TelemetryEndpoint` (`internal/shared/telemetry.go:25`,
`https://telemetry.wdkro.de/v1/count`) is now live — the maintainer set it up in
`wdk-ansible`. This release verifies the path end to end rather than assuming it:
a real report, sent and counted.

`EASYWALL_WEB_TELEMETRY` exists so the public demo reports. Note plainly in the
documentation that a demo instance counts as one installation, so the number
means "installations including the demo".

Consent semantics do not change: unset still means no.

## 6 · Documentation — a reference page, not an explanation

New page under `docs/_docs/installation/`, of one Diátaxis type only:
**reference**. It carries the precedence table from §2, a Mermaid diagram of the
three layers, and one row per variable — the TOML key it sets and whether a
control exists for it. The *why* of the inversion goes in the CHANGELOG under
*Changed*; it does not belong on a reference page.

`docs-tech/invariants.md` gains the presence-detection guard from §1.

## 7 · Scope

In: the precedence inversion, the provenance marker and reset control,
`EASYWALL_WEB_TELEMETRY`, telemetry verified live, the four `hx-trigger`
removals, the reference page, the roadmap renumbering.

Out: anything about proxies or the audit log's addresses — that is 2.13.
