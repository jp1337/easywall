Search crawlers, webhooks and monitoring must pass. A feed applies to every port, so a list that is safe for SSH only is not safe for the host.

**blocklist.de "all" should not stay recommended.** Replace it as the recommended brute-force list with
`https://lists.blocklist.de/lists/ssh.txt` (new id, e.g. `blocklist-de-ssh`). Keep `blocklist-de` as ✗,
its confirm box naming search crawlers and uptime monitors. Merging `imap.txt`, `ftp.txt`, `sip.txt`,
`strongips.txt` into the SSH feed (URLs merge already) stays crawler-free in every sample, but adds lists
that matter only to a host running those services.

Consequences for the repository (not done here):
- `docs/_docs/features/feeds.md`: the warning names Googlebot and Bingbot only; measured also Google special crawlers, Applebot, StatusCake, and Cloudflare (a proxied origin's own front door). The "Measured 2026-09-24" table is stale (§5).
- Existing installs that switched `blocklist-de` on keep it on; a verdict change does not switch anything off.
