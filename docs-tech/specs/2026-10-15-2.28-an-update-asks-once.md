# 2.28 — An update asks once

After a minor or major update, the dashboard asks once whether this installation
may be counted, unless it already is. The question is a card on the page, not a
page you have to get past. Its three answers are *Yes*, *No* and *Don't ask
again*.

**Why now.** Counting is off unless switched on (2.12). Only the first-run
wizard asks, so every installation set up before the wizard, and every *No*
given there, stays uncounted forever. Without asking again, the counter cannot
say how many installations exist or which versions they run.

## 0 · Decisions, and what decided them

| # | Decision | Evidence |
|---|---|---|
| D1 | **Shown when all of these hold:** counting is off (`TelemetryEnabled()` false), the running minor version has not been answered, *Don't ask again* was never chosen, `EASYWALL_WEB_TELEMETRY` is unset, and the process is not in demo mode. | The maintainer: "nicht angezeigt, wenn die Telemetrie bereits aktiv ist". A set variable means the deployment decided (Ansible on root01xvp), and answering in the interface would override it, because a stored value beats the variable (`config/web.toml` § Counting). The demo has no reporter (`server.go`: `telemetry` is nil in demo mode). |
| D2 | **Asked again after a *No*, with *Don't ask again* as the way out.** | The maintainer's choice, from three options. Asking without that way out reads as pressure on a consent question. |
| D3 | **Only a new minor or major version asks**: `2.27.x → 2.28.0` asks, `2.28.0 → 2.28.1` does not. The key is `major.minor` of `shared.CurrentVersion`. A pre-release counts as its minor. A version that does not parse (a `dev` build) never asks. | The maintainer's choice. Five patch releases shipped in two days (2.25.1–2.27.1). |
| D4 | **Every explicit answer records the minor**, wherever it is given: the card, the first-run wizard and the System toggle. The reset button on System records nothing. | Without this, a fresh 2.28 install that leaves the wizard's box unticked would be asked again on its first dashboard. An answer given on System this minor is an answer. |
| D5 | **A card at the top of the dashboard**, below the update banner. It is not a page between login and the dashboard, and it never appears on other pages. | Someone logging in to press *Panic* or roll back must not have to answer a question first. The dashboard is where a login lands (`/`). |
| D6 | **The card says what is sent**: the request line `GET https://telemetry.wdkro.de/v1/count?id=…&v=…`, once a day, and that the address is not recorded at the other end. It links to the configuration page. | The same claim System makes (`TelemetryEndpoint` on the page). A consent question that does not say what it consents to is not one. |
| D7 | ***Yes* and *No* are equal buttons**: same class, same size, same order in both themes. *Don't ask again* is a plain link-styled submit. Nothing is pre-selected. | DESIGN.md has no consent pattern. An answer the interface leans towards is not an answer. |
| D8 | **Stored in `<data_dir>/web/telemetry_prompt.json`** as `{"asked": "2.28", "never": false}`, not in `web.toml`. | It is state, not configuration: Ansible templates `web.toml` and has no business holding "asked on 2.28". The name joins `stateFiles` (`statedir.go`), which `TestEveryWebStatePathIsInTheStateDir` holds to the paths. Deleting the file means the next dashboard asks again; the configuration page says so. |
| D9 | **A failed write of the marker does not fail the answer.** *Yes* and *No* save `telemetry` through `SaveTelemetry` first; a failure there is `save_error`, the same as on System. A failed marker write is a warning in the log, and the card asks again next time. | The consent is the part that must not be lost. The marker only decides whether the question is asked. |
| D10 | **This release is 2.28.** Every later roadmap entry moves down one (metrics becomes 2.29, and so on). | The maintainer wants it built now. Countries was pulled forward the same way for 2.26. |

## 1 · Web

- `shared.MinorVersion(v string) (string, bool)`: `"2.28.0-rc1"` gives `"2.28", true`; `"dev"` gives `"", false`. It is built on the existing `splitVersion`.
- A small `promptStore` in `internal/web` reads and writes `telemetry_prompt.json` under its own mutex, written with `writeFileAtomic` (`tlscert.go`). A missing or unreadable file reads as never asked.
- `dashboardData` gains `AskTelemetry bool`, computed from D1 on every GET.
- `POST /telemetry/prompt` with `answer=yes|no|never`, behind the authentication and CSRF middleware like every other POST. `yes` and `no` call `SaveTelemetry` and then record the minor. `never` records `never: true` and leaves `telemetry` as it is. Any other value is a 400. With htmx the card is removed out of band and a flash says what was saved. Without htmx the answer redirects to `/`.
- The wizard's `completeFirstRun` and `handleTelemetryPOST` (not its reset branch) record the minor after a successful save.

## 2 · Interface and copy

- The card is a `card` with a `section-head`, the same structure as System's sections, and shows the request line in monospace. Three controls, as D7 describes. At 390 px the buttons stack, full width.
- Locale keys (en, de; fr may have gaps): `telemetry_prompt_title`, `telemetry_prompt_body`, `telemetry_prompt_yes`, `telemetry_prompt_no`, `telemetry_prompt_never`, `telemetry_prompt_saved_yes`, `telemetry_prompt_saved_no`, `telemetry_prompt_saved_never`.

## 3 · Documentation

- `configuration.md` § Counting: when the question comes back, how to stop it, and that `telemetry_prompt.json` holds the answer.
- `environment.md`: a set `EASYWALL_WEB_TELEMETRY` also means the interface never asks.
- `privacy.md` and `datenschutz.md`: nothing about what is sent changes. One sentence says that the interface asks again after an update.
- The dashboard screenshots stay as they are, because the demo never shows the card (D1). One new screenshot of the card, both themes, in `configuration.md`.
- CHANGELOG 2.28. The roadmap is renumbered (D10).

## 5 · Out of scope

- Asking on pages other than the dashboard.
- A reminder after a delay, or a *Later* button. Leaving the card unanswered is *later*.
- Any change to what is sent or how often.
- A switch on System to bring the question back. Deleting `telemetry_prompt.json` does that.
