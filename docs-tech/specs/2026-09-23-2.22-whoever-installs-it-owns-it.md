# 2.22 — Whoever installs it owns it

From wdk-ansible's audit of the Docker path against v2.21.0, re-checked
against the source. The operator's goal: **a plain `docker compose up -d` is
enough**, with no Ansible and no feature pages read first. Today it is not,
and on both install paths the first visitor to `/firstrun` owns the firewall.

None of this was caused by 2.21 — every item predates it — so it is a release
of its own, and a minor one: the first-run form gains a required field,
compose mounts a new directory, and `easywall-web` gains a flag. The roadmap
rows from 2.22 on move one place: this spec and
[the 2.23 one](2026-09-23-2.23-every-switch-says-what-it-breaks.md) ship
together as 2.22.

## Decisions

| Question | Decision | Why |
|---|---|---|
| **B** — how a claimant proves it installed this | A **setup token**: 160 bits from `newTOTPSecret()`, generated by easywall-web at start only while no account exists, held in memory, printed once as a `slog.Warn` line (→ `docker logs`, the journal). A required field on step 1, compared with `subtle.ConstantTimeCompare` after `decodeTOTPSecret` normalises it, **before** the password is hashed | Of six projects read at pinned tags, only Jupyter (token in the log) and Nextcloud (`CAN_INSTALL` file) make the claimant prove host access; Home Assistant and Gitea are first-come, as easywall is today. Checking first also closes X1. One check covers confirm and recover, which require step 1's pending entry |
| Which process holds it | **easywall-web** | Account creation is already the web process's alone; the core never sees credentials. Putting it in the root process would add a protocol command and an authentication duty it has none of |
| Lifetime | Until the account exists or the process restarts; a restart prints a new one, which is also the recovery for a lost line. No timeout, no file, no environment variable | Nothing on disk to leak through a backup; secrets stay out of the environment layer (`env.go:25-28`). Automation that writes `password` directly never sees a token |
| Loopback-only default instead | **Rejected** | Breaks the documented remote-first flow (`docker.md:23`) and forces `ssh -L`, which fails under common hardening (I). `EASYWALL_WEB_BIND_ADDR` already gives loopback to whoever wants it |
| Debian | Same code. `postinst` prints one line: where to open `/firstrun`, and `journalctl -u easywall-web -g 'setup token'` | It cannot print the token itself — the web process makes it |
| Demo | No exemption | The public demo ships with a password set, so it never sees a token; a self-hosted demo writes a real `web.toml` and needs the gate. `demo.md` rewritten (X4) |
| **A** | `docker.enabled = true` in the shipped `easywall.toml`, both paths | Identical to `false` on a host with no bridges; on a Docker host it is the host's own behaviour without easywall. Cost: an interface named `br-*` that is not Docker's is trusted — the key's comment says so. An environment variable is ruled out by `TestNoEnvVarTargetsARuleField`. New installs only; existing files are never overwritten |
| **K** | compose mounts `./easywall-config` (gitignored); the entrypoint seeds it from the image's template | The image already carries the defaults, so no `config.example/`. Existing installs move their files once — the command is in the changelog and `docker.md`, and B keeps the first run that follows from being claimable |
| **D** | Pin uid 100 / gid 101 — the values already shipped, so no existing volume changes owner; the entrypoint sets `/var/lib/easywall` to `root:easywall 0770` and adds it to its `test -w` check. `/var/log/easywall` stays root's | The web process never touches `log_dir`; the core and supervisord do |
| **C** | `easywall-web -healthcheck`: loads the config without writing anything, derives the target from `bind_addr`, exits 0 on a 200. `/healthz` also admits a peer whose address equals the connection's local address | No script; honours the file and the variable. A completed handshake from our own address is a local process, as trusted as loopback. The HEALTHCHECK stays shell form (`build.yml:228` reads `Test[1]`). CLAUDE.md's "`easywall-web` takes nothing else" changes |
| **F** | Recommend a pinned `:vX.Y.Z` and a deliberate `pull && up -d`; say that a recreate restores the rules with no window; name Watchtower as archived or drop it | A firewall that updates itself unconfirmed is the opposite of the acceptance window |
| Docs E, G–J, L, X2–X5 | One-liners where the research names them; G as a Debian / Docker two-column table | — |
| CI | One new step in `build-image`: *compose, as documented*, with a bridge-network override and empty bind mounts. It asserts the token line, a refused POST without it, `enabled = true` seeded, `/var/lib/easywall` writable by the web user, and `healthy` with a moved bind | There is no compose test today (`ci-and-release.md:76-86`); each assertion is one of A–D, verified by breaking the code it covers |

**Order:** B first (independent, and it makes K's migration safe), then A,
then K (it builds the CI step D and C reuse), then D, C, docs.

**Unverified, stated once:** the live container outage in A; X1's memory
cost; whether compose runs from a bare `docker-compose.yml` without the
checkout while `build:` is present.

## Found while planning

Each measured at v2.21.1, none caused by 2.21, all fixed in this release.

| # | Finding | Measured | Plan |
|---|---|---|---|
| P1 | **The web user can make the root core write anywhere.** `/var/lib/easywall` is `root:easywall 0770` with no sticky bit, so the web process can replace the core's files, plant `last_apply -> /etc/shadow` (the core's `os.WriteFile` follows it), swap `rules.json` (restored at boot with no window), or plant a `panic` marker that keeps the firewall down at every start | done as uid 100 in the container; `debian/postinst:39`, `Dockerfile:77`, `firewall.go:241` | Task 14: `data_dir` becomes `root:easywall 0750`, the web keeps its state in `data_dir/web`, both paths migrate safely, the core writes atomically and refuses to trust a writable `data_dir` |
| P2 | A signed-out htmx request swaps `/login` into the page | the 303 from `RequireAuth` is followed by the XHR; seen in /blocked's table | Task 10 |
| P3 | The lockout check counts a port rule that only filters forwarded traffic | `Reachable` ignores `FiltersHost()` (`reach.go:217`), the input chain does not (`nftables.go:805`) | Task 12 |
| P4 | An IPv4-mapped network (`::ffff:10.0.0.0/104`) makes the blacklist, the whitelist and a bogon exception fail every apply with `EINVAL`, and is skipped as a port source | measured rootless | Task 13 writes it as the IPv4 network it names; nothing is refused |
| P5 | Four protection switches do not do what they say: fragment drop matches nothing (the input chain sees reassembled packets), ICMP flood never sees an IPv6 ping, TCP RST flood sees almost nothing behind *Invalid packets*, the blacklist log skips network entries | measured in a netns on kernel 7.2.3 | Task 11 |
| P6 | `debian/control` does not depend on `adduser`, which `postinst` calls | `debian/control:20`, `postinst:8-11` | Task 14, Step A |
