# 2.23 — It says what it breaks, and why it refused

Asked on 2026-09-23: */options* is too complicated for someone without much
networking knowledge — *"Drop multicast" has no description, no help, nothing;
users do not know what they are doing and cannot read up on it.*

Measured against the source, the premise is half right. Every one of the
fourteen switches **has** a one-line description, in `en` and `de`, unchanged
since `643becc`. None of them says what the switch **breaks**, who should turn
it on, or where to read more — and the page that answers all three,
`docs/_docs/features/filters.md`, is linked from nowhere on /options.

The measurements behind every row: [the research](2026-09-23-2.23-research.md). Its F6 row on fragment drop was wrong against `filters.md:24` and is corrected here.

## Findings

| # | Finding | Measured |
|---|---|---|
| F1 | Every description states *what is dropped*, never *what stops working* or *who wants it* | all 14 `opt_*_desc` in `locales/en.json`; e.g. "Discards traffic sent to a multicast group" |
| F2 | /options links to no documentation; `filters.md` already has a *Which to turn on* table, per-module defaults and the breakage for bogon, broadcast, multicast and anycast | `options.html`: the only link is `/apply` in the save bar; `filters.md:18-26, 87-160` |
| F3 | *Drop multicast* drops mDNS (Avahi, `.local`), SSDP/DLNA and every other UDP multicast. IPv6 neighbour discovery and router advertisements survive only because the ICMP accepts sit earlier in the chain | `addMulticastDrop` matches `pkttype` alone (`nftables.go:1923`); `addICMPRules` at `:721` runs before the modules at `:739-775` |
| F4 | *Drop broadcast* does not stop a first DHCP lease on a `systemd-networkd` host, but does drop a broadcast reply to a renewing client | lease acquisition uses an `AF_PACKET` socket (`sd-dhcp-client.c:1408`, v257), whose copy is taken in `__netif_receive_skb_core` (`net/core/dev.c:5512-5630`, v6.12) before `ip_rcv` reaches the netfilter hooks (`ip_input.c:254, 569`); after the lease it is a UDP socket (`sd-dhcp-client.c:1857`) and netfilter applies. Other DHCP clients: unmeasured |
| F5 | *Fragment drop* is IPv4-only; its description does not say so | `addFragmentDrop` checks the IPv4 fragment offset only (`nftables.go:1231`) |
| F6 | The shipped defaults are the cautious home/NAT case; for a public server `filters.md` recommends *everything under Attack protection* — which includes the connection limit and TCP RST flood, both off by default — plus the bogon filter, and nothing on /options says so | `config/easywall.toml`; `filters.md:22-26` |
| F7 | `options_readonly` is a dead key that says options need a core restart — false since options save live | no reference outside `locales/*.json`; `handler_options.go:27` |

## Decisions

| Question | Decision | Why |
|---|---|---|
| Shape | Each module card keeps its one line and gains a native `<details>` — *What does this change?* — with three short lines: **protects against**, **can break**, **turn it on if**, and a link to its section of `filters.md` | DESIGN.md forbids decision-relevant text in a tooltip (`:1553`); `<details>` is already shipped on /blocked, needs no JavaScript, works by keyboard and touch |
| The one-liners | Rewritten to lead with the consequence where there is one: *Drop multicast* → "Blocks local discovery (mDNS, DLNA). Leave off on a home network." | The line a reader sees without opening anything must carry the decision; the disclosure carries the reasoning |
| Which to turn on | One card above the grid: the three host types from `filters.md` (*public server*, *home network or behind NAT*, *container host*), each with the switches it wants, linking to `#which-to-turn-on` | Answers F6 without state. The table already exists; the page only has to show it |
| Presets | **Not in this release.** A preset is state — which one is active, when it becomes *Custom*, a second copy of the table — for the same answer the card above gives in text | Named so it is not forgotten; it earns its own release if operators ask for one click |
| Docs link | Absolute `https://easywall-project.org/docs/features/filters/#<anchor>`, through `richText` | The precedent is `password.html:342`; the interface has no base-URL setting and needs none |
| Where the facts live | One Go table in `internal/web` maps each option to its locale keys and its `filters.md` anchor; the template ranges over it | Fourteen hand-copied blocks drift. A guard test reads the table: every option has all keys in `en` and `de`, and every anchor is a real heading in `filters.md` |
| `filters.md` | Gains the *can break* lines F3–F5 measured, so the page the interface links to says what the interface says | A link to a page that says less than the card is a dead end |
| Dead key | `options_readonly` removed from every locale | F7 |
| `fr` | New keys are added to `en` and `de` only; `fr` falls back to English, and the coverage report counts it | The repository's rule; the gap grows by the number of new keys and the PR says the number |

**Not in this release:** presets; the numeric parameters' labels (*Max rate*,
*Log limit/min*) beyond saying their unit and scope in the disclosure.

## Every refusal says why

Asked the same day, from the live /blocked page on root01xvp: nearly every
row reads *Default drop* — *could it say why, e.g. which option?*

*Default drop* means **no option refused the packet — nothing allowed it.** A
module that refuses names itself (*Port scan*, *SSH brute force*); the final
drop is what is left when no accept matched. So its *why* is what was missing,
and that is answerable from the rules.

| # | Finding | Measured |
|---|---|---|
| G1 | A default-drop row names no cause; the operator has to work out that port 993/tcp has no rule | `blocked_rule_drop` is the whole cell |
| G2 | An IPv4 ping always ends in the default drop, while an IPv6 ping is answered | ICMPv4 accepts 0, 3, 11, 12 only (`nftables.go:1159`), ICMPv6 accepts 128 (`:1187`); *ICMP flood* only rate-limits echo requests and accepts nothing under the rate (`addPerSourceRateLimit` jumps only when over). Documented in `filters.md` *Always on*, visible nowhere on /blocked |
| G3 | The packet log does not record the ICMP type, so an ICMP row cannot say it was a ping | `PacketLogEntry` has no ICMP type field (`internal/shared/packetlog.go:21-51`) |
| G4 | A module row's chip names the option but does not lead to it | `blocked.html` renders `blocked_rule_<rule>` as plain text |

| Question | Decision | Why |
|---|---|---|
| What a default-drop row says | One short reason under the chip, derived from the **current** rules: *port 993/tcp is not open*; *993/tcp is open only for 10.0.0.0/8*; *993/tcp is open now — this arrived before it was*; *IPv4 pings are not answered*; *ICMP type N is not accepted*. No forward-chain reason: that chain has no log rule, so no forward row reaches the page | Every sentence is a fact the page can check, and each leads to the action the row already offers |
| Where it is computed | One function in `internal/shared` beside `Remedies`, walking the port and ICMP steps in chain order, with a reason code per case and a locale key per code — the `ReachReason` pattern | A sentence assembled in Go cannot be translated (`reach.go:35-37`); a guard test pins every code to both locales |
| "Now", not "then" | The reason says what the rules say **now**, and says so when they changed since | The ruleset at the packet's time is not stored, and storing it per packet costs more than the question is worth |
| ICMP type | The core's decoder records the ICMP type (and code) into the entry, one byte each; the protocol gains the field additively | G3; without it an ICMP row can only say *ICMP*. The single core change in this release |
| IPv4 ping | **Behaviour unchanged here.** The row says it plainly, and `filters.md` states the asymmetry | Whether to answer IPv4 pings is a policy change and needs its own decision; this release makes it visible |
| Module rows | The chip links to that option's card on /options (the anchors this release adds) | G4 — "which option" becomes one click |

## Done when

- Every switch on /options answers *what breaks* on the page, in both
  languages, and links to the section that explains it.
- The guard test above is red when a key or an anchor is removed (verified by
  removing one).
- Every default-drop row on /blocked carries a reason; every reason code has
  both locale keys (guard test, verified by removing one); an ICMP row names
  its type.
- /options rendered in Chrome at 1600, 900 and 390 px, both themes, `en` and
  `de`, with a disclosure open; `options-{light,dark}.png` re-taken.
